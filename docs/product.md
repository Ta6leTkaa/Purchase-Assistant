# Первый продукт

Цель: сократить ручной ввод данных семьи при покупке билетов, сохранив проверку пользователем.

## Первый сценарий

1. Пользователь открывает поддерживаемую форму в своём браузере.
2. Выбирает людей и видит порядок их распределения.
3. Проверяет найденные поля и разрешает ввод документов для этой операции.
4. Расширение заполняет поля; пользователь проверяет результат и сам отправляет заказ.

## Границы текущей версии

Каркас расширения Manifest V3, TypeScript, синтетическая семья и одна локальная форма.
Нет настоящего хранилища профилей, реальных интеграций, ИИ, оплаты и покупки.
Расширение не отправляет сетевые запросы и не хранит введённые значения.
Открытый исходный код не означает публикацию расширения в Chrome Web Store.

## Следующие этапы

- Выбрать первый реальный сайт, изучить форму, очередь, блокировку мест и момент ввода данных.
- Зафиксировать поля: отчество, гражданство, тип документа, контакты и различие покупателя/участника.
- Подготовить обезличенные фикстуры реальных групп полей, включая динамические формы.
- Сделать адаптер сайта с явным сопоставлением людей и предварительной проверкой всех полей.
- Спроектировать защищённое локальное хранилище: разблокировка, ключи, удаление, резервирование; не хранить ключ рядом с шифротекстом.
- Добавить браузерные end-to-end тесты установки расширения и выполнения сценария.
- Замерить ручной ввод и автоматическое заполнение для 1/2/4 людей; зафиксировать p50/p95, долю ошибок и условия измерения.

## Условия готовности первого реального сценария

Данные не смешиваются между участниками; неоднозначность останавливает ввод;
нет скрытой отправки формы, платежей или перезаписи чужих значений;
результат проверен повторными прогонами на целевом сайте.
Скорость измеряется от нажатия «Заполнить» до окончания ввода; загрузка сайта учитывается отдельно.
Гарантии наличия или покупки дефицитных билетов не даём.
